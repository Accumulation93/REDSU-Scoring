# WHUSU Smart Workspace 领域架构

本文件描述人事领域整改后的稳定架构契约。数据库结构以 `server/db/init.sql` 与已执行迁移为事实来源；代码与本文不一致时，应核实实现并使其收敛到本契约，不得重新引入旧的单岗位人员快照模型。

## 人事领域实体

```text
自然人 person
├── 全局账号 account（跨组织，不属于任何单一组织）
└── 组织成员关系 membership（自然人 × 组织）
    └── 岗位 assignment（0..n）
        ├── 岗位性质 assignmentNature
        ├── 部门 department
        ├── 身份类别 identityCategory
        └── 职能组 workGroup（可选，必须属于该部门）
```

- 自然人保存姓名、学号等跨组织身份信息；组织成员关系保存加入、在职、离开等组织关系状态。
- 组织成员可以在职但没有岗位。删除最后一个岗位不等于离开组织，离开组织也不删除自然人、全局账号或历史。
- `membership_assignments` 是岗位唯一事实来源。自由文本岗位名称不属于领域模型，不得保存、导入、判权或展示。
- 岗位性质对应现有 `assignment_kind`，业务值固定解释为本会岗位、学院对接岗位、其他岗位；它描述岗位来源/性质，不等于身份类别。
- 岗位展示名 `assignmentLabel` 由“身份类别 · 部门 · 职能组”生成；职能组为空时省略该段。岗位性质单独显示和筛选，不与展示名混为自由文本。
- 同一成员关系内，岗位性质、部门、身份类别、职能组完全相同的在职岗位只能存在一条。新增、编辑和人员合并都必须在成员关系行锁内检查该岗位元组，禁止用重复岗位制造第二个工作角色。

## 工作角色、岗位与内部上下文命名

- `contextId`：可登录、可切换的内部工作上下文 ID，只用于接口、存储和判权。
- `activeContextId`：小程序当前内部上下文的唯一持久化键。
- `assignmentId`：当前具体岗位 ID；无岗位成员的成员上下文中为空。
- `identityCategoryId/Name`：岗位中的身份类别字典值。
- `assignmentNature`、`assignmentLabel`：岗位性质和生成的展示名。

跨岗位与管理权限的通用用户界面统一称“工作角色”，具体详情分别称“岗位”与“管理权限”。“工作上下文”、`contextId`、快照、字段映射等技术词不得进入用户提示、标题或操作文案。

旧 `identityId`、`activeIdentityId`、`selection.identityId` 只允许兼容读取/映射一轮。服务端不得以这些旧字段授权，前端不得继续写入或广播。身份类别不是登录上下文，也不是岗位。

显式工作角色切换采用“原子激活 + 重建页面栈”模型：服务端返回的新令牌、组织、角色、`contextId`、资料和权限先形成一份统一运行时状态，随后小程序只执行一次 `reLaunch` 回到门户。禁止根据旧页面是否支持新角色决定返回旧页；所有子应用从新门户再次进入并执行完整初始化。门户主题、角色信息和入口权限也只由这份状态派生，兼容 storage 不得反向参与判权或主题选择。

## 授权边界

- 当前组织决定租户边界；当前岗位决定审核、场地和评分的岗位规则权限。任何模块不得从 `hr_info` 的部门、身份类别或职能组兼容快照推导当前权限。
- 无岗位成员可以登录、查看组织公共内容和维护个人资料，但不能发起或处理岗位规则驱动的审核、场地审批和评分动作。
- 跨组织通知和待办可以在全局视图汇总；执行动作前必须进入目标组织并切换到满足原规则的当前岗位。
- 汇总不是扩大权限：每个组织、每个工作角色都必须独立重新计算待办资格，禁止只凭“管理员”或“同一自然人”展示受保护数据。通知目标页按接收角色生成并在切换成功后打开；资料审核等管理待办不得跳入普通用户页面。
- 候选筛选与最终执行是两次授权检查。人员在候选生成后调岗、离任或切换岗位时，执行端必须按当前岗位重新校验。
- 审批状态机一次命令只能推进一条确定路线。并行路线完成一条后，其余路线进入 `superseded` 语义，不得记为完成；同一岗位连续自动通过只允许跨越规则完全等价的相邻岗位步骤，不得跨越管理员步骤、指定岗位或责任范围变化。
- 创建待审批事实必须与审批配置使用同一事务和配置锁，冻结规则、申请岗位和流程定义，并在写入前证明至少一条首步路线存在有效候选人。执行阶段只读取冻结事实；损坏、缺失或互相矛盾的状态与快照失败关闭，禁止用当前配置猜测修补。
- 消息中心是跨组织聚合视图，不是授权来源。实时待办从当前业务状态与当前岗位计算；持久通知按组织、业务事件和收件人幂等投递。消息跳转先激活目标组织/岗位，目标详情再按资源事实独立授权；通知清除不改变待办或业务状态。
- 通知只有在目标页面导航成功且服务端确认写入后才可记为已读。跨组织/岗位跳转先原子激活目标工作角色、重建门户页面栈，再由新门户使用绑定通知、组织、角色和目标路由的短时一次性内存回执完成目标导航并回写已读；切换、导航、回执校验或写入任一失败都保留未读。待办从不因点击、跳转或通知清除而被客户端销记。
- 审核附件的访问分成“资源授权”和“存储完整性”两层：组织、管理员细权限、提交/待审/历史岗位或验签授权通过后，还必须确认文件路径位于受控根目录，并核对大小与 SHA-256。任何一层失败都不得下发文件字节。

## 不可变历史快照

审核发起/步骤处理、场地申请/审批和评分记录必须保存操作发生时的：

- 组织 ID 与组织名称；
- `contextId` 与 `assignmentId`；
- 岗位性质；
- 部门、身份类别、职能组的 ID 与名称；
- 操作者自然人标识及业务需要的显示名。

历史详情只读上述快照。调岗、字典改名或离开组织不得改写历史含义；旧数据确实缺少快照时仅可显示“历史岗位信息缺失”，授权必须失败关闭，禁止使用自然人相同、管理员身份、`hr_info` 或当前岗位猜测授权。

审批条件中的指定部门、身份类别和职能组当前以逗号分隔集合保存，表示同一维度内的 OR。它们必须在组织锁内拆分逐项校验，不能建立标量外键或把整串值当成一个 ID；历史条件快照不可修改。

## 资料与账号治理

- 资料审核状态和资料完整度独立计算。存在待审提交时状态始终为 `pending`，缺少必填项只影响完整度。
- 人员维护者维护已生效资料；资料审核员比较、通过或填写原因驳回待审资料，不得直接写入生效值。资料记录、全局生效值和审核历史在同一事务中变更。
- 资料审核以组织内不可变的成员记录 ID（`hrId`）定位待审记录；学号只用于展示、搜索和一轮旧客户端兼容，不得作为新请求的审核主键。姓名纠错时，成员记录、资料记录和管理身份中的显示名必须一并传播。
- 姓名和学号属于自然人的受控全局纠错。姓名变更先预览影响范围再传播；学号冲突进入显式自然人合并流程，带版本校验、事务和审计。
- 冻结、解绑、初始化或修改登录口令、重置全局账号只允许 `auth.accounts.global_manage`。该权限必须同时允许读取当前组织的成员治理目录和账号状态，否则不得展示账号治理入口；它不自动授予资料维护、岗位编辑或跨组织读取权限。组织管理员只能查看合并账号状态，不得影响自然人在其他组织的账号使用。在职成员没有账号时，口令初始化事务锁定自然人并创建唯一的 `verified` 全局账号；已有账号只更新凭据，不改变冻结等状态，也不撤销会话。
- 口令认证先验证全局账号凭据。账号已有微信绑定时兼容未提交微信登录 code 的旧客户端；没有绑定时必须交换本次 `wx.login` code，并在同一受控流程中只补充空绑定、同步兼容映射后再创建会话。任何既有绑定或绑定冲突都不得被覆盖。
- 登录会话不绑定设备安装标识。微信绑定、账号状态和工作角色有效即允许登录；设备型号等信息只允许作为登录后的可选展示元数据，同一账号在多台设备上的会话相互独立。
- 访问令牌自动续期必须携带续期前的 `activeContextId` 与组织标识，并由服务端重新验证。只有续期后的组织、角色和工作上下文与原请求一致时，原请求才允许重放；原工作角色已失效而发生服务端回退时，客户端必须取消原请求并重建门户页面栈，禁止在回退角色下静默执行旧操作。
- 登录和工作角色切换的临界路径以内存会话为唯一同步事实来源。OpenHarmony 等真机上的本地持久化只能在会话生效后异步写入，目录刷新、提示传递和兼容键落盘不得阻塞认证回调或角色切换完成。
- 已存在全局账号但尚未绑定微信的成员显示为“待激活”，只有确实不存在账号时才显示“未创建账号”；两者不得合并为同一筛选状态。

## 成员目录、离任与永久删除

- 成员资料目录是组织成员关系的唯一管理目录，一次返回当前权限范围内的全部在职与已离开成员；离任不是第二类人员，不得建立独立“已离开成员”目录、页签或重复接口调用链。
- 已离开成员保留离任前岗位、组织资料、账号状态和历史，只读展示并允许重新加入；离任必须在同一事务中撤销岗位并清空 `hr_info` 的当前岗位兼容快照，历史岗位只能从离任批次读取。重新加入只恢复为“在职、无岗位”，不得自动恢复已撤销岗位，也不得让兼容快照重新产生岗位权限。
- “离开当前组织”是可恢复的成员关系状态变更，并同步撤销当前组织普通管理员授权、权限覆盖及管理员上下文会话；全局超级管理员治理权不受组织离任影响。“永久删除组织成员记录”和“彻底删除自然人”是不可逆的数据治理动作，三者必须使用不同接口、权限、文案和审计语义。
- 永久删除必须先执行全引用预检。审核、场地、评分、资料审核历史等已产生业务事实的记录一律阻断；未执行的人员指定、组织授权、会话、邀请和恢复数据可以在事务中清理。清理指定人员后造成零候选的模板、步骤或规则必须停用并返回待修复清单，禁止扩大候选范围。
- 组织范围永久删除只影响当前组织，保留自然人在其他组织的成员关系和全局账号；彻底删除自然人仅限超级管理员，且必须先检查全部组织。当前操作者和最后一名有效超级管理员不可删除。
- 删除预检与执行使用事务、行锁、并发版本和幂等键；预检版本失效必须重新预检。同一次受控确认在首次执行前生成一个稳定的客户端幂等键，网络重试复用该键，关闭弹窗、切换目标或重新预检后必须废弃；禁止每次重试重新生成，也禁止执行时漏传。彻底删除后只保留去标识审计，不保留姓名、学号或可反向关联自然人的明文字段。

## 绝对时间与日期型数据

- 数据库存储时区固定为 UTC，所有绝对时间使用 UTC `DATETIME(3)`；`system_config.timezone` 只表示系统显示时区偏移，不得改变数据库、连接池或会话的存储语义。
- 服务端绝对时间统一返回 ISO UTC；客户端必须使用系统下发并缓存的 `systemTimezoneOffset` 与配置版本转换显示，禁止使用设备本地时区推断。
- `YYYY-MM-DD` 的纯日期、`HH:mm` 的每日开放时间、时长、提前量和周期规则是日期型/规则型值，不是绝对时间，禁止做时区换算。跨模块接口和字段设计必须明确区分这两类值。
- 人事补充资料中的日期字段只接受无时间、无时区的日历日期并归一化为 `YYYY-MM-DD`；禁止把 ISO 时间戳、设备本地时间或任意 `Date` 解析结果截成日期，以免跨时区漂移。
- 列表中的绝对时间统一显示到分钟 `YYYY-MM-DD HH:mm`；详情、验签和安全记录显示到秒 `YYYY-MM-DD HH:mm:ss`。WXML/视图层只接收预计算的 `*Text` 字段，不得直接渲染原始时间或 ISO `T...Z` 字符串。
- 历史时间只按已确认的写入来源校正。数据库 `NOW()/CURRENT_TIMESTAMP` 形成的本地墙上时间与代码已写入的 UTC 必须分流处理；来源无法可靠判定的记录进入迁移审计并标记“历史时区待核对”，禁止猜测平移。
- 可证明由旧 UTC+8 数据库墙上时间生成的字段减 480 分钟转为 UTC；混合来源字段以主键游标和有界批次物化逐记录待核对账本，不做整列平移。响应中按“记录标识 + 原始绝对时间”追加对应 `*ReviewStatus`，客户端逐字段标记。存在未解决记录时 cutover 使用 `review_pending`，并要求展示映射数与未解决数完全一致；仅未解决数为零时使用 `verified`。离任等历史事实时间不得因关系回填触发 `ON UPDATE` 而被覆盖。

## 字典完整性

- 部门、身份类别和职能组保存时校验组织归属；岗位使用职能组时还要校验“职能组所属部门 = 岗位部门”。
- 任一字典项只要曾被岗位、审核模板/快照、场地规则/快照、评分规则/记录、印章、发布权限或历史引用，就禁止删除。
- 删除检查返回引用类别与数量，不做级联删除、自动替换或停用绕过。

## 模块依赖方向

- `server/src/core` 提供自然人、组织成员、岗位、内部上下文、资料、账号和字典能力。
- 审核、场地、评分模块只消费规范化上下文和岗位接口，不复制人事目录，也不直接以 `hr_info` 判权。
- 小程序统一通过 `authContext`/`orgSession` 管理 `activeContextId`；业务页面不自行维护第二套上下文缓存。

## 平台托管密码凭证 v2

审核动作在组织/岗位鉴权和事务行锁内，经 `approvalSigningEvidence` 为当前附件产生凭证，`auditFileCommitCoordinator` 协调文件版本和事务。`audit_signing_evidence` 保存不可变 CMS、加密身份和事件/文件引用；`audit_signing_certificates` 保存组织范围的受控证书登记。清理必须保留凭证引用路径。

`signingEvidenceProtocol` 负责 JCS、HMAC/AES 身份绑定和步骤链，`cmsSignature` 是唯一 CMS 实现，`pdfVerification` 在受限 Worker 内验证实际 PDF 字节及签名对象。`signingVerification` 聚合身份、事件、文件和证书结果，前端复用 `audit-verification-result`。密钥仅在受保护版本化文件及独立副本，不属于数据库配置。协议、OID、API、历史边界及自动配置见 [签署隐私与密码验签](pdf-signing-trust.md)。
