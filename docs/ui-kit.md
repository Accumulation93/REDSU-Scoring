# WHUSU Smart Workspace UI Kit

本文件是微信小程序前端视觉规范的事实来源。运行时令牌位于
`miniprogram/app.wxss`，组件清单见 `docs/ui-components.md`，页面模板见
`docs/ui-page-templates.md`。

## 设计方向

- 蓝色轻奢玻璃：浅蓝渐变背景、半透明白色表面、细边框、内高光和克制阴影。
- 管理页面优先使用紧凑的工作台布局；不使用营销页式的大面积留白。
- 业务逻辑和页面结构可以有差异，但基础字体角色、控件角色、弹窗契约和状态表达必须可预测。
- 原生微信小程序和自有 WXSS 是当前 UI provider；不引入 React、Tailwind 或第三方组件库。

## 控制表面与卡片操作

- 页面分区标题、二级页签和成组操作必须归属于至少一层真实可见的玻璃表面。`.page`、`.admin-workbench`、`.section-stack` 等透明布局容器不算包裹；禁止标题、页签或按钮组直接裸露在页面背景上。
- 同一分区优先用 `.section-control-card` 共同承载标题、二级页签和批量操作，保持信息层级连续。不得给每个控件分别重复套卡，也不得为包裹新增滚动容器。
- 列表卡片上的查看、编辑、删除、移除等小操作使用 `.card-actions`。默认独立成行、顶部细分隔、右对齐、可换行，并复用人事成员卡片操作样式；最小宽度、间距和分隔留白分别使用 `--ui-card-action-min-width`、`--ui-card-action-gap`、`--ui-card-action-divider-gap`，圆角使用 `--ui-control-radius`。
- 危险操作保持红色语义；`.card-actions--inline` 仅用于已确认不会与标题、状态或展开入口冲突的紧凑行。禁止用绝对定位、固定 `top/right`、负 margin 把操作塞进卡片头部。
- 可展开卡片按“摘要与展开入口 → 操作行 → 展开内容”的普通文档流排列。审核模板卡的编辑、删除必须另起操作行，不能与展开按钮重叠。
- 同一视觉行的日期/时间选择器、筛选按钮和清除/重置按钮使用 `.ui-inline-control-row` + `.ui-inline-control`，共同高度由 `--ui-inline-control-height` 提供。带标签的并列筛选字段使用 `.ui-inline-field-row` 对齐实际控件底边，并统一 `.compact-picker-value` / `.field-input` 高度；原生输入保持 block。子项上下 margin 必须为零，禁止同名共享样式把某一个按钮单独向下推移。
- 标题右侧的宫格/列表等二态切换使用 `.ui-compact-segmented` + `.ui-compact-segmented-item`，高度取 `--ui-compact-height`，宽度按内容收缩；它不是主页签，不得复用整行均分和 `--ui-tab-min-height`。
- 同一管理工作台的顶层页签不允许换行形成孤立的第二行，也不能因换行、裁切或权限刷新让末项看似消失。可见页签不超过五项时必须在同一玻璃分段控件内等宽单行排列，子项允许收缩但文字不得拆字；更多页签必须使用明确的横向滚动方案，并保证当前项自动进入可视区。
- 从详情页返回已有卡片目录时，目录保持可见并以后台刷新更新状态；不得为一次增量刷新重新展示整页加载占位。只有首次进入、筛选口径变化或工作角色切换导致旧数据不再适用时，才使用阻断式首屏加载。
- `scripts/ui-audit.js --strict` 将裸露标题/分区控件、未迁移的 `list-actions` 和审核模板绝对定位操作视为发布失败。

## 人事信息界面契约

- 人事信息只保留“成员资料 / 认证设置”两个模式。成员资料默认合并展示在职和已离开成员，禁止独立“已离开成员”页签或第二套列表；目录坚持“一名自然人一张成员卡”。
- 成员卡只显示姓名、学号、成员状态、合并账号状态、资料状态、岗位数量，以及已离开成员的离任时间。多个岗位只在成员详情中分组，不得把同一人按岗位复制成多张卡；无岗位在职成员显示中性气泡，已离开成员显示灰蓝气泡。
- 岗位编辑字段顺序固定为岗位性质、部门、身份类别、职能组；职能组随部门联动且可空。禁止自由文本岗位名称，展示名由“身份类别 · 部门 · 职能组”自动生成，缺少职能组时省略。
- 工作角色选择器展示组织及“岗位/管理权限”类型；“身份类别”只作为岗位维度，不得替代岗位。用户界面统一使用“工作角色”“岗位”“管理权限”，禁止显示“工作上下文”或内部 `contextId`；前端内部状态仍统一使用 `activeContextId`。
- 工作角色切换成功后固定回到门户并销毁旧页面栈；禁止因旧页面在新角色下仍可用而返回复用。门户顶部角色卡、工作角色文字和应用入口必须读取同一份当前会话：管理权限使用深蓝管理主题，岗位使用标准蓝主题，视觉与权限必须同步。
- 资料状态和完整度使用两个独立状态表达。存在待审值时始终显示待审核；生效值/待审值对照卡先显示字段名，再显示两侧值。手机纵向排列，Pad 可双列，但阅读顺序和操作语义不变。
- 生效资料维护与待审资料审核不得混在同一操作组。驳回使用受控弹窗并要求填写原因；账号冻结、解绑、重置只对全局账号治理者显示。
- “离开当前组织”使用组织范围的危险操作文案，不得写成删除成员；确认层明确自然人、账号和历史不会被删除。
- 查询字段选择器、关键词、排序、高级筛选和批量工具共同放在一张 `.section-control-card`。高级筛选直接在卡内展开，不创建嵌套窗口；已选条件使用共享紧凑气泡，可逐项清除和全部重置。手机按内容采用单列/双列组合，Pad 使用紧凑网格。
- 卡片式选择器统一使用 `.selection-option-card`。每张卡只表示一个可选单元；人员按岗位选择时一张卡对应一个“人员 · 岗位”。独立的 `.select-chip.selection-card-toggle` 必须位于卡片左上、作为第一个可见子项，未选显示“选择”、已选显示绿色“取消”。身份类别、部门、职能组、岗位和状态气泡只表达信息，禁止附带“已选”或承担选择事件；已选列表不得用整行“移除”操作替代左上取消控件。
- 多岗位筛选必须以岗位元组为视觉和数据单位：岗位性质、部门、身份类别、职能组必须在同一岗位中共同成立；已离开成员使用离任前岗位匹配，并在结果或详情明确标注历史岗位。禁止跨岗位拼接筛选命中。
- 账号治理、认证授权、验签授权等按自然人选择的明确例外可以使用人员 ID，但候选卡仍须列出该人的全部岗位，并同时提供部门、身份类别、职能组三项筛选。筛选条件必须命中同一岗位元组，禁止使用人员顶层兼容字段；手机端三项岗位筛选同排、搜索另起一行，Pad 可在空间充足时合并为一行。
- 按岗位选择人员时使用 `assignmentId` 作为选中键；只有账号治理、认证授权等明确按自然人的选择器可以使用人员 ID。导航型或选择后立即关闭的单选卡可以不显示选择/取消，但禁止把信息气泡改造成选择状态。规则卡若兼有编辑/删除，把选择摘要和操作行分层，不能挤在同一媒体行。
- 已离开成员详情为只读，保留离任前岗位、组织资料、账号状态和历史，只提供“重新加入”；重新加入后显示为在职无岗位。永久删除操作仅位于详情底部危险操作区，红色语义不得扩散到普通离任或只读信息。
- 删除预检弹窗采用固定标题、滚动正文、固定操作栏，正文按“阻断记录 / 自动清理 / 将停用的规则”分组；彻底删除自然人还必须提供学号确认输入。长弹窗高度内容驱动且受视口安全上限约束，手机、Pad 竖屏、Pad 横屏都必须能滚动到底并操作。
- 部门、身份类别、职能组列表必须区分加载中、成功空数据和加载失败。加载失败时保留最近一次成功数据，并在列表表面显示明确失败说明和原地重试；首次加载失败且没有旧数据时只显示失败态，绝不能清空列表后展示“暂无数据”。
- 删除字典项若服务端返回引用明细，前端必须用受控玻璃弹窗逐项展示引用类别和数量；不得把明细丢弃后只显示 Toast。弹窗保持固定标题、可滚动正文和固定关闭操作，不提供级联删除、自动替换或绕过引用的操作。
- 新增管理员属于自然人级授权，但候选检索和岗位展示必须遍历 `assignments` 全部岗位元组；第二岗位的岗位性质、部门、身份类别或职能组必须可以命中。候选卡按人员保留一张，并在卡内逐岗位展示完整标签；禁止读取人员顶层旧部门/身份/职能组快照。

## 时间信息界面契约

- 所有绝对时间由页面根据系统配置时区预计算后进入视图，禁止跟随设备本地时区，也禁止把 ISO `T...Z` 原文直接绑定到 WXML。
- 列表和成员卡时间统一使用 `YYYY-MM-DD HH:mm`；详情、验签、安全记录和删除预检使用 `YYYY-MM-DD HH:mm:ss`。时间属于元数据字阶，不以高饱和气泡抢占主状态。
- 纯日期、每日时刻、时长、提前量和周期规则保持业务格式，不做时区换算；页面标签必须让用户能区分“日期/每日时间”与“发生时间”。
- 历史来源无法确认的绝对时间仍按统一格式显示，并由同一业务对象的字段级 `*ReviewStatus` 在相邻灰蓝提示中标记“历史时区待核对”；禁止使用全局布尔值给所有时间加标记，也禁止漏传状态或回退显示裸 ISO。

## 高危操作与异步状态契约

- 冻结、解绑、重置凭据、撤销恢复码、永久删除、删除规则/用途等高影响操作必须使用受控确认弹窗。标题点明动作，正文显示目标、范围和数量，底部取消/确认固定可达；执行前冻结确认快照，取消不发请求，加载中禁止重复提交。
- 危险色只标识真实危险操作，不能用颜色替代确认，也不能把危险按钮与普通查看/编辑混在同一紧凑触控区。批量危险操作必须明确“当前筛选结果”还是“已选成员”，禁止依赖用户猜测。
- 页面隐藏、卸载或切换组织/工作上下文时必须停止轮询、延迟同步和重试计时器；迟到回调在写界面前再次核对页面与上下文。界面不得因上一组织的定时器覆盖当前数据。
- 文本字数提示按 Unicode 字符计数，emoji 和扩展字符按一个用户感知码点处理；前端展示上限必须与服务端一致。

## 页面组织与语言资源

- 主包启动壳统一物理放在 `miniprogram/subpackages/main/pages/**`，登录页和门户页注册在 `app.json.pages` 顶层；`subpackages/main` 不得写入 `app.json.subPackages`。包归属以 `app.json` 注册位置为准，不以目录名为准。
- 消息中心、工作台和其他业务页面统一放在 `subpackages/<模块名>/pages/**` 并注册到 `app.json.subPackages`，不得把业务页注册到顶层主包。
- 分包只能引用自身分包或主包资源，禁止跨业务分包引用；跨模块共享 WXSS 统一放在 `miniprogram/subpackages/main/styles/**`，共享组件和基础逻辑统一放在 `miniprogram/components/**`、`miniprogram/utils/**`、`miniprogram/locales/**`。
- 复杂页面必须按语义区拆分自定义组件；成员筛选控制卡、危险操作弹窗、评分详情等不得继续堆进一个超大 WXML。发布前运行 `node scripts/wechat-template-runtime-audit.js`：本机使用微信开发者工具自带 Glass-Easel 编译全部模板并解析生成代码，CI 无编译器时执行单模板元素数量硬门禁。出现生成变量名为 `if` 等保留字、任何 `Unexpected token` 或超过复杂度上限时必须继续拆组件，禁止用删空白或改固定值绕过。
- 分包迁移必须同步更新 `app.json`、门户卡片、可信导航、上下文守卫、服务端通知/待办目标和 WXSS 导入路径；旧主包业务路由不得残留在生产调用链。
- 提示、指引、校验反馈、空状态、Toast、Modal、确认层、通知标题/描述和导出标题等用户可见常量只能来自 locale。业务代码通过语义键和格式化参数引用；CSV 列别名、状态码、路由和内部日志不属于文案。
- locale 生成必须合并现有文件与 Git 基线资源，禁止覆盖同文件已有键；迁移后必须重跑语言审计和受影响功能测试。
- 发布前必须通过 `node scripts/user-visible-copy-audit.js --localization-prefix=miniprogram/ --strict-localization`、`node scripts/user-visible-copy-audit.js --localization-prefix=server/src/ --strict-localization` 和 `node scripts/user-visible-copy-audit.js --strict-guidance`。

## 设备层级

设备差异是设计的一部分，不能把所有设备压成一套尺寸。

| 层级 | 条件 | 字体特点 | 布局特点 |
| --- | --- | --- | --- |
| 紧凑手机 | `<390px` | 最小可读字号，避免弹窗放大 | rpx 触控间距，单列为主 |
| 标准手机 | `390–519px` | 比紧凑手机略大一级 | 保留手机卡片密度和两列摘要 |
| Pad 竖屏 | `≥520px` | 使用逻辑 px，所有正文角色大于手机 | 卡片和控件变矮变密，内容列居中 |
| Pad 横屏/大屏 | `≥900px` 且 landscape | 字号仍大于手机，但控件高度进一步收紧 | 工作区铺满可用宽度，页签整行均分 |

响应式断点只改变设备层级，不改变语义角色顺序：元数据 < 标签/正文 < 强调值 < 分区标题 < 页面标题。

## 运行时令牌

默认令牌定义在 `page { ... }` 中，并在媒体查询中覆盖；由于 `viewport-portal` 的 RootPortal 不保证继承页面变量，弹窗关键令牌必须在 `.ui-overlay` / `.ui-sheet-overlay` 上直接同步声明。页面级 WXSS 不应重新猜测这些基础值。

### 字体

| 角色 | 用途 |
| --- | --- |
| `--ui-type-micro` | 极弱辅助信息 |
| `--ui-type-caption` | 时间、数量、次要说明 |
| `--ui-type-meta` | 描述、地点、状态详情 |
| `--ui-type-label` | 表单标签、轻量操作 |
| `--ui-type-control` | 页签、按钮和控件文字 |
| `--ui-type-body` | 正文 |
| `--ui-type-emphasis` | 强调信息 |
| `--ui-type-value` | 列表标题、重要值 |
| `--ui-type-section` | 卡片和分区标题 |
| `--ui-type-page` | Hero 或页面主标题 |

弹窗使用独立紧凑字阶：`--ui-dialog-title-size`、`--ui-dialog-body-size`、
`--ui-dialog-meta-size`、`--ui-dialog-label-size`、`--ui-dialog-control-size`。

### 间距与几何

| 令牌 | 语义 |
| --- | --- |
| `--ui-page-padding-*` | 页面安全边距 |
| `--ui-hero-*` | Hero 内边距、圆角和与正文的距离 |
| `--ui-card-*` | 主要玻璃卡片内边距、圆角和卡片间距 |
| `--ui-list-*` | 重复列表项的间距、内边距和圆角 |
| `--ui-field-gap` | 相邻表单字段之间的垂直距离 |
| `--ui-label-gap` | 字段标签与所属控件之间的距离 |
| `--ui-inline-gap` | 同一行内关联控件、图标和文字之间的距离 |
| `--ui-action-gap` | 正文或内容表面与独立操作区之间的距离 |
| `--ui-page-action-gap` | 页面底部成组主操作之间的专用距离，禁止复用较小的行内间距 |
| `--ui-footer-gap` | 品牌页脚与上方操作组或内容区之间的专用距离，由页脚语义容器持有 |
| `--ui-compact-padding-*` | 标签、气泡和紧凑操作中文字到控件边缘的内距 |
| `--ui-control-radius` | 主按钮和大控件圆角（手机 28rpx、Pad 竖屏 14px、Pad 横屏 12px） |
| `--ui-compact-radius` | 状态标签、筛选标签和紧凑操作圆角（手机 18rpx、Pad 竖屏 12px、Pad 横屏 11px） |
| `--ui-field-radius` | 输入、选择器和表单控件圆角 |
| `--ui-tab-*` | 页签字号、高度、内边距和圆角（手机 24rpx、Pad 竖屏与横屏 12px） |
| `--ui-inline-control-height` | 同排日期/时间选择器、筛选与清除操作的统一物理高度（手机 56rpx、Pad 32px） |
| `--ui-section-title-inset` | 标题蓝色竖线与标题文字的距离 |
| `--ui-dialog-edge` | 弹窗与物理视口的安全边距 |
| `--ui-dialog-width-inset` | 弹窗横向两侧安全边距之和，供兼容性良好的 `calc()` 使用 |
| `--ui-dialog-height-inset` | 弹窗纵向两侧安全边距之和，供最大高度计算使用 |
| `--ui-dialog-padding` | 弹窗表面的对称内边距 |
| `--ui-dialog-section-gap` | 弹窗标题、正文分组和控件之间的间距 |
| `--ui-dialog-footer-gap` | 弹窗正文与底部操作区的距离 |
| `--ui-dialog-radius` | 弹窗表面圆角 |

圆角按设备上调一档并保持统一：按钮、页签、选择项和状态气泡全部使用柔和圆角矩形，且圆角必须明显小于控件高度的一半。

- 手机：主按钮 `28rpx`、页签 `24rpx`、紧凑操作与状态气泡 `18rpx`。
- Pad 竖屏：主按钮 `14px`、页签与紧凑控件 `12px`。
- Pad 横屏：主按钮与页签 `12px`、紧凑控件 `11px`。

卡片、输入框和弹窗外壳维持各自原有圆角，不随按钮体系连带放大。页面级 WXSS 不得用固定数值覆盖以上令牌；头像、加载圈、进度节点、纯图标圆钮等真正圆形元素仍可保留圆形。

严格 UI 审计会拦截任何控件类的固定圆角偏差：除 `999rpx/50%` 圆形例外外，固定值必须命中对应设备档位（紧凑 `18rpx/12px/11px`、按钮 `28rpx/14px/12px`、页签 `24rpx/12px/12px`），否则视为违反规范。

预览列表（门户待办/通知等）使用令牌化最大高度 + 框内滚动：`--ui-message-preview-row` / `--ui-message-preview-gap` 定义单条高度与间距，盒子 `height: auto; max-height: calc(row * 3 + gap * 2)`，禁止按条目数估算高度或预留固定视口；表单底部操作区与容器底边由容器统一提供对称留白。

### 间距所有权硬契约

- 每一段可见空白只能有一个几何所有者。页面边缘由 `.page` 负责，卡片内容边缘由卡片 `padding` 负责，列表项间距由列表父级 `gap` 或同一套相邻项规则负责，正文到操作区由 `--ui-action-gap` / `.ui-dialog-footer` 负责。禁止父级 `padding`、子级 `margin` 和空白占位节点为同一方向重复叠加。
- 普通页面必须使用 `--ui-page-padding-*` 并保留底部安全区；页面级 WXSS 不得再用固定 `padding-bottom` 猜测底部距离。普通内容由实际内容撑开，禁止用固定高度、`min-height` 或大块尾部 padding 制造版面留白；专业时间表、虚拟键盘等确有覆盖层的工作区必须在局部类中说明原因。
- 表单字段之间使用 `--ui-field-gap`，标签到所属控件使用 `--ui-label-gap`，同排关联控件使用 `--ui-inline-gap`。最后一个字段若后接独立操作区，不得继续保留字段尾部 margin；控件文字到边缘分别使用 `--ui-control-padding-*` 或 `--ui-compact-padding-*`，禁止以空格字符、固定行高或额外包裹层代替内边距。
- 弹窗创建/编辑表单固定采用“标题 / 可滚动正文 / 独立操作区”三段式。提交、保存和取消按钮必须位于滚动正文之外的直接子级 `.ui-dialog-footer`；按钮自身 `margin: 0`，正文与按钮的距离只由操作区控制，按钮到底边的距离只由弹窗外壳控制。禁止把按钮放进正文后再用正文底部 padding 伪造操作区。
- 页面内联编辑必须与新增态构成可逆闭环：进入编辑后显示明确“取消”，取消只清理编辑对象和临时输入并恢复新增态，不发保存请求；再次点击当前编辑项或切换同级页签不得成为唯一退出方式。编辑态没有可见退出操作视为阻断性 UI 缺陷。
- 控件使用 `min-height + 对称 padding + 语义 line-height`；禁止同时堆叠固定 `height`、固定 `line-height` 和上下 padding。多行文案必须自然增高，不能为了视觉居中裁掉文字；上下内距和左右内距要按同一设备令牌成对核对。
- 手机、Pad 竖屏、Pad 横屏分别使用运行时令牌中的独立值，不能把手机 `rpx` 直接放大到 Pad。每次间距修改必须逐页阅读 WXML/WXSS，说明间距归属和业务语义，并现场核对首项、末项、空状态、长文案、滚动到底和安全区；脚本只能做回归门禁，不能代替人工判断。

### 媒体行与消息卡硬契约

- 左侧图标、多行正文和尾部操作采用受控三段布局；正文必须 `min-width:0`，多行卡顶部对齐。图标图片不得超出图标槽。
- `ui-icon` 业务调用使用 `sizeRole` 语义档位，由组件分别定义手机 rpx、Pad 竖屏 px、Pad 横屏 px。固定 px 图标槽内不得继续使用随屏幕放大的数值 rpx 图标。
- 门户和消息中心的业务类别与岗位组成明确上下文行，组织名称和“当前”独占下一整行。组织名称保持完整，空间不足时只在该语义行内按词自然换行、不得拆字；“当前”固定不收缩。
- 页面底部双主操作使用 `--ui-page-action-gap`，Pad 起默认两列；品牌页脚使用 `--ui-footer-gap`。二者置于共同语义容器中，外层 Grid 不能替代或清空内部间距。

## 共享交互契约

- `.page` 是页面外壳；页面内容必须由内容撑开，不为普通卡片预留视口高度。
- `.hero` / `.hero-admin` 是页面头部；认证后的页面优先复用 `workspace-hero`。
- `.card`、`.section`、`.edit-box`、`.list-card` 是主要玻璃表面。
- `.tabs`、`.tabs-card`、`.tab` 使用共享页签令牌；横屏页签必须整行均分或明确横向滚动。
- `.primary-btn`、`.secondary-btn`、`.danger-btn` 是三种主按钮角色；小型操作使用链接式控件。
- 账号认证不是独立视觉域：管理端并入人事信息的“账号与认证”，普通用户并入人事信息的“账号与登录”，两端都复用现有人事卡片、人员行、筛选器和设备密度。
- 凭据表单的主要保存操作必须使用标准主按钮规格。普通用户“保存口令”独占一行并全宽显示；管理端使用“保存口令 / 取消”标准双按钮行。两处按钮高度、字号、圆角和垂直留白与“保存人事信息”一致，禁止复用 `.compact-action`。
- 纵向 Flex 表单中的全宽主按钮必须显式使用 `flex: none`，并通过 `box-sizing: border-box` 与 `width/min-width/max-width: 100%` 固定横轴。双列按钮类的 `flex-basis: 50%` 不得泄漏到纵向表单，否则会被解释为高度并导致按钮巨高或半宽；三档设备验收必须核对最终盒模型。
- 大型人员目录在当前权限范围内完整获取，并在本地筛选；单人状态变更只更新对应列表行，不能用全页加载状态打断用户。
- `.ui-overlay` 和 `.ui-dialog-shell` 是弹窗唯一几何所有者：全局只允许一处几何定义，遮罩固定覆盖 `100vw × 100vh`，弹窗以 `50vw / 50vh` 为锚点居中。
- `viewport-portal` 会把弹窗提升到 `RootPortal` 原生顶层宿主。所有 `--ui-dialog-*`、弹窗字号和颜色令牌必须同时直接声明在 `.ui-overlay` / `.ui-sheet-overlay` 上，禁止只依赖 `page` 的变量继承；否则宽度和内边距声明会整体失效。
- `.ui-overlay-blocker` 只负责阻止背景触摸；弹窗壳不滚动，正文由直接子级 `scroll-view.ui-dialog-body` 滚动，嵌套列表继续使用 `nested-scroll-enabled`。
- 普通 WXML 不写静态 `style` 或 `placeholder-style`。进度宽度、时间表坐标、拖拽位置、动画延时等运行时几何可以保留动态行内样式；其余表现必须进入语义类并引用设备令牌。
- 页面返回、组织与工作上下文切换、登录失效等系统行为使用现有共享流程，不在页面内重新实现一套。
- 评分页的首次评分和重新评分使用同一套可编辑界面：已有评分仅预填当前分数，不显示“已评分”“可修改”“旧版本”等横幅或气泡；点击题目必须在一次状态更新中同步当前题、快捷分值和键盘展开态，提交时原子覆盖当前评分。只有缺少可验证题目范围的异常记录才显示“这条评分暂时无法修改，请联系管理员”。题目使用“题号气泡 + 正文标题 + 最高分气泡”，模板卡底部只保留“小计 + 分值”；标题、小计、总分均使用正文/强调/数值语义字号，禁止使用页面标题字号造成手机或 Pad 碎行。快捷按钮使用弹性双轴居中、对称内距和自然行高；三档设备不得混用固定高度、等高行高和继承内距。
- 评分页必须对载入时与当前题目分数进行精确比较。仅分数变化时显示原生离页确认，恢复原值或提交成功后解除；返回按钮、系统手势及导航切换不得无提示丢弃草稿，键盘开合、题目焦点和校验状态不得误报未提交。
- 管理端场地借用使用顶部玻璃分段页签独立呈现“待我审批”；待办页内的“审批历史”入口每次从当前组织全部借用记录实时匹配当前操作者、当前工作上下文和岗位的不可变审批快照，不得使用单独历史表，也不能用全组织借用列表代替。旧记录缺少岗位快照时显示历史授权信息不足并失败关闭，禁止用自然人、管理员身份、`hr_info` 或当前岗位放行。历史页不放刷新按钮；每条记录只保留一张可点击卡片，处理时间、步骤和意见统一放入详情页，并在详情页展示后续审批进展。
- 普通用户端必须在“待我审批”页签内提供“审批历史”入口，不得放在“我的借用”页或借用记录区域。审批历史详情、日程点击详情和我的借用点击详情必须复用同一个借用详情组件与数据形状；服务端先完成当前组织、当前工作上下文、当前岗位和当前操作者的历史权限匹配，再返回可展示详情。审批进度必须同时携带全部 `flowSteps` 与 `snapshots`，显示已完成步数取数据库当前步骤和快照最高已完成步骤的并集并限制在总步骤内，确保后续步骤完成后不会停留在旧进度。

### 审批步骤详情展开规范

- 审批步骤卡的展开态必须与审核子应用 `submissionDetail` 统一：展开详情必须放在同一张 `.flow-info` 卡片内部，禁止作为卡片外的兄弟节点；可视卡片本身必须同步添加 `.flow-info-expanded`，不能只在祖先节点添加状态后依赖偶然的 CSS 顺序。展开时 `.flow-info-expanded` 必须以高于 `.flow-node-done/.flow-node-rejected .flow-info` 的优先级切换为白色玻璃层，不能继续保留已通过/驳回的绿色或红色背景。
- 流程卡基础、展开层、提示和详情排版只允许在 `subpackages/main/styles/home.wxss` 维护一份。场地与审核页面统一使用 `.flow-expand-detail`、`.flow-detail-processed-text`、`.flow-detail-processed-meta`、`.flow-detail-comment`；页面或组件不得复制第二套尺寸和颜色。自定义详情组件通过 `styleIsolation: apply-shared` 接收调用页已导入的共享样式，禁止在组件 WXSS 中直接导入页面级 WXSS。审批意见只在展开详情中显示，收起态不再重复一份，以免信息顺序、字体和间距漂移。每次改动至少核对已通过、已驳回两种卡片的收起态与展开态。

### 场地借用规则编辑器

- 规则编辑弹窗采用审批子应用同款三段式结构：标题固定，正文由直接子级 `scroll-view.ui-dialog-body` 独立滚动，底部保存栏固定在 `ui-dialog-footer`，禁止把保存按钮放进正文滚动区域。窗口高度由标题、正文实际内容和底部操作栏动态分配，只设置基于视口安全区计算的动态上限；禁止固定正文高度、固定翻页尺度或固定像素偏移，允许 `max-height: calc(100vh - 安全区)` 作为溢出保护。
- 审批流卡片必须把“允许指定第一步审批人”与“允许指定下一步审批人”显示为两个独立开关，与流程选择开关同属 `.flow-switch-row` 并允许自然换行。两个开关不得共用选中状态、合并文案或互相改写。
- 步骤和审批条件参考审核子应用模板步骤展开卡片：步骤卡使用统一编号、标题和操作区；每条条件使用紧凑强调卡，部门、职能组、身份类别按语义行展示并自然换行，不得制造大块留白；编辑条件时只显示条件编辑器，不得与步骤编辑器叠加。
- 条件为“指定”时，步骤卡片、步骤编辑器和条件编辑器都必须显示实际的部门、职能组、身份类别名称，禁止只写“指定部门/指定职能组/指定身份类别”。名称从统一字典预计算，字典异步完成后刷新，长名称在标签内自然换行。
- 步骤/条件子编辑器必须用明确的 `null` 表示关闭；取消不写回并立即关闭，保存先将副本应用到上级步骤/规则列表，再关闭子编辑器。
- 所有原有步骤名称、审批模式、条件选择、添加/编辑/删除、取消和保存行为必须保留。规则数量增加后，手机与 Pad 竖横屏都必须能滚动到正文底部并点击保存。
- 步骤条件卡必须采用“条件关系标题 + 部门/职能组/身份类别三行语义字段”的扫读结构，范围值使用深色正文、标签使用弱化颜色并允许自然换行，禁止连续蓝色小号文字堆叠。
- 添加步骤、编辑步骤、添加条件和编辑条件后，必须通过滚动容器语义定位把对应编辑器自动带入可视区，不得写死 scrollTop/像素偏移，也不得要求用户自行翻找；关闭编辑器时清理定位状态。
- UI 变更后必须完成 UI 审计、兼容性审计、差异检查，并现场操作验证打开编辑器、添加步骤、编辑条件、滚动到底和保存。
- 借用规则编辑器还必须提供独立的借用时间窗口策略：开放与截止分别支持不设置、提前天数、提前小时/分钟；开放未设置表示无最早时间，截止未设置表示借用开始时间晚于当前即可提交。策略按组织与场地保存，由服务端动态校验。
- 用户端场地卡片展示时间窗口时，开放提交和截止提交必须与“需审核/直接通过”使用同一彩色状态气泡体系并处于同一个状态行；文案使用“开放提交 不限/开放提交 X 日前/开放提交 X 小时 Y 分钟前”和“截止提交 借用前/截止提交 X 日前/截止提交 X 小时 Y 分钟前”；禁止嵌套浅色块或出现“开放：不限制前”等内部拼接文案。
- 用户端日程整列点击、日期选择、时间输入和时间条拖动必须共享同一套有效性判定；已过去、不在场地开放时段、超出借用窗口或发生占用冲突的时间不得打开或写入，日期/时间选择无效时保留上一次有效值并给出明确提示。
- 借用时间窗口必须在规则管理中作为与开放时间、活动时间、借用规则并列的独立设置页签直接编辑保存，不得嵌套在借用规则或审批步骤编辑弹窗内，字段和按钮沿用规则管理现有列表样式。
- 活动占用规则必须先选择每天/每周/每月/每年周期，再在周期下互斥勾选“按生效时间范围”或“按重复次数”；不勾选表示不限周期范围。仅展示当前选项字段，时间范围与重复次数不得另造为周期页签或模式。管理端活动记录卡片与用户端/管理端日程活动块必须可点击，并使用同一活动详情弹窗展示本次占用时间和规则说明。
- 消息中心通知列表在有通知时提供二次确认的“全部清除”，只清除当前消息范围的通知，不影响待我审批事项。
- 审核提交/编辑页的模板步骤预览中，第一步若允许指定审批人，必须在第一步步骤卡内部提供“指定/修改指定”紧凑入口；选择器按具体岗位列出“姓名 · 身份类别 · 部门 · 职能组”，同一自然人的不同岗位为独立选项。已指定人员岗位直接以气泡显示在同一张步骤卡内，可按岗位移除。禁止再渲染独立的“第一步审批人”卡片；第一步不允许指定时不显示该入口。

## 签名板与文件定位坐标硬契约

签名板、白板、文件预览定位和最终图片/PDF 合成必须共享同一套坐标定义，任何页面级视觉改动都不得破坏：

- 可视白板和实时笔迹全部使用普通 `view`，严禁使用可视原生 Canvas。白板、触点和笔迹事实数据统一为视口 CSS px（逻辑像素）绝对坐标。
- 白板通过 `.fields({ size:true, rect:true })` 获取绝对边界；每次完成布局、尺寸变化或弹窗重新显示后重新测量；触点只读取 `clientX/clientY`，裁切后保存为 `screenX/screenY`。禁止 scrollTop、状态栏、标题栏、弹窗 top、DPR、rpx 或经验偏移。
- 实时线段保存绝对端点，渲染普通视图时才减一次白板 `rect.left/top`；白板和笔迹层必须裁切溢出。
- 原生 Canvas 只能是透明、不可交互的导出器。确认时将绝对端点投影到白板局部坐标，导出 buffer 与白板宽高保持 1:1，禁止 DPR 放大。
- 书写位置只保存为相对于实际文件预览图的归一化中心点 `positionX/positionY`（0–1）。点击必须读取预览图自己的 viewport 矩形，不能使用弹窗或 scroll-view 矩形代替。
- 预览签名保持原始图片宽高比，禁止固定 `rpx` 高度或人工高度；服务端图片、PDF 和 PDF 签名域只能读取同一中心点，每个坐标系只执行一次 y 轴转换。
- `clientX/clientY` 只能和 viewport 矩形配对，禁止将 `pageX/pageY` 与 client 矩形直接混算；0 和 1 是有效边界值，不得用 `value || fallback` 覆盖。
- 修改后必须用真实鼠标/触控事件验证指针与普通视图笔迹逐点重合；禁止直接调用组件方法或隐藏 Canvas 生成测试线。再验证导出图片、预览定位和最终文件；未验证的范围不得宣称通过。

## 审批人员选择与重指定契约

- 模板修改时，仅当模板第一步开启“允许指定审批人”时显示第一步指定入口；未开启时不显示，也不能通过接口绕过。
- 驳回重提交创建新轮次时，模板步骤恢复模板原始候选条件；当前审批人收到某一步后，仅在下一步开启允许指定时显示人员选择器。
- 人员选择器只使用审批专用的当前组织岗位候选人接口，部门、身份类别、职能组在弹窗内本地筛选，不能调用管理员专用人事目录接口。
- 审批人员选择器的候选区和已选区必须遵循同一左上选择控件契约。正文列 `flex:1; min-width:0`，选择控件不收缩；禁止把整行 `.card-actions` 放进人员媒体行，避免姓名和岗位标签被压成逐字窄列。
- 服务端必须再次校验当前审批权限、步骤开关、组织隔离和被指定人员是否满足原始模板条件。
- 全仓审批、评优、授权和场地指定人员弹窗统一使用 `miniprogram/components/personnel-picker/`。组件采用左上“选择/取消”、已选区、候选区、固定底栏和确认写回；禁止整卡点击后立即关闭。`assignment` 模式一岗一卡并返回岗位 ID，`person` 模式一人一卡但展示全部岗位，同一岗位元组完成部门、身份类别、职能组三项筛选。

### 共享人员选择器契约

- 属性：`visible`、`title`、`options`、`value`、`selectionLevel`、`multiple`、`loading`、`errorText`、`contextText`；提交中使用 `confirmLoading`。事件只允许 `confirm`（`{ keys, items }`）、`cancel` 和 `retry`。
- 岗位候选至少提供 `personId`、`name`、`studentId`、`assignmentId`，并提供部门、身份类别、职能组、岗位名称/摘要；自然人候选以 `personId` 去重，`assignments` 保留全部岗位元组。同一自然人的不同岗位在 `assignment` 模式中不得合并。
- `value` 只用于弹窗打开时初始化草稿。选择、取消单项和清空均只改变组件草稿；只有底栏确认才写回页面，关闭或取消不得修改页面状态。可选指定必须接受空数组。
- 手机 `<520px` 使用 `rpx` 令牌；Pad 竖屏 `520-899px` 弹窗最大宽 `760px`、候选区最大高 `300px`；Pad 横屏 `>=900px` 弹窗最大宽 `1024px`、候选区最大高 `260px`。三档均保持标题和底栏固定、正文独立滚动，最后一项后保留尾部滚动空间。
- 候选区与已选区统一使用 `.selection-option-card > .select-chip.selection-card-toggle + 正文`。仅左上选择控件具有点击反馈；卡片壳、头像、岗位信息和插槽内容不得连带位移或缩放。

## 样式所有权

1. 全局令牌和基础契约：`miniprogram/app.wxss`
2. 共享组件：`miniprogram/components/`
3. 子应用特殊布局：对应页面 WXSS
4. 业务状态和内容：对应页面 JS/WXML

页面 WXSS 可以改变布局方向、列数和内容排列，但不应覆盖全局字体角色、设备断点、弹窗定位、按钮角色或基础控件高度。控件圆角必须直接引用 `--ui-control-radius` / `--ui-compact-radius` / `--ui-tab-radius`，页面级源码不得保留 `999rpx` 胶囊或与令牌不一致的固定值；头像、加载圈、进度节点、纯图标圆钮等真正圆形元素除外。
页面级弹窗类可以定义业务内容排列，但不得再次声明遮罩定位、弹窗中心点或独立的视口边距。

## 更新规则

- 新增组件前先查组件清单和页面模板。
- 新增可复用模式时，先补令牌或共享组件，再写页面局部样式。
- 改变字体、间距、圆角或断点时，同步更新本文件和 `miniprogram/app.wxss` 注释。
- UI 变更至少运行 `node scripts/ui-audit.js --strict`、`node scripts/miniprogram-compat-audit.js` 和 `git diff --check`，并在手机、Pad 竖屏、Pad 横屏各看一次。用户明确要求人工审计时，必须逐段阅读和定向代码核对，不能用脚本扫描结果代替自然语言判断。

## 弹窗内部层级（2026-08）

- 弹窗默认只有“外壳 + 正文表面”两个视觉层级。功能分区仅用于摘要、筛选、独立列表或两个以上确实不同的业务区域，禁止为了统一形式固定套成三层。
- 所有普通弹窗正文使用 `.ui-dialog-content`；多个兄弟分区共同存在时叠加 `.ui-dialog-content--stack`，让正文只负责滚动和间距。时间表、签名定位等专业工作区叠加 `.ui-dialog-content--workspace`；短确认框使用 `.ui-dialog-compact-content`。
- `.ui-dialog-stack` 是无背景、无边框、无圆角、无额外内边距的布局容器。单一表单或详情直接由正文表面承载，不得再用 `.ui-dialog-section` 或页面级 `.form-body / .detail-body / .detail-popup-form` 绘制同质内卡。
- 功能分区使用 `.ui-dialog-section`、`.ui-dialog-summary`、`.ui-dialog-toolbar`、`.ui-dialog-list-panel`。`.ui-dialog-section` 只允许用于两个以上具有独立语义的兄弟分区，禁止包裹正文中的唯一内容。
- 手机使用约 `32rpx` 外壳留白、`18rpx` 正文留白和 `22rpx` 分区留白；Pad 竖屏为 `24px / 14px / 16px`；Pad 横屏为 `22px / 12px / 14px`。设备差异必须保留，不能用横屏压缩值覆盖手机。
- 可滚动列表必须能翻到底并完整显示最后一项：在滚动内容末尾放置小号尾部留白（约 `24–32rpx`，如 `.scroll-tail-space`），最后一张卡片下边缘可完整翻出并可再翻一小段；滚动容器自身的 `padding` 不产生可滚动距离，禁止最后一项被裁切或“翻不到底”。
- 手机常规弹窗横向只保留必要的屏幕安全边距，Pad 竖屏常规上限为 `760px`，Pad 横屏常规上限为 `1024px`、专业宽窗口上限为 `1120px`。窗口应充分利用可视宽度，内部则保留清晰的四向留白，不能用收窄窗口代替内容排版。
- 标题、正文卡片和底部操作左右对齐；同一垂直间距只能由一层负责。正文与内层列表保持原有滚动契约，增加卡片表面不得引入新的滚动容器。

## 人事治理与设备识别（2026-08）

- 管理端的人员认证、账号状态和恢复操作直接进入成员资料体系，不另建人员认证或账号恢复目录。成员外卡和详情摘要只保留同一个合并账号状态；详情中的账号与认证分区不再用“当前状态”“微信绑定”或“恢复方式”卡片重复表达该状态，只展示确实需要查看或操作的认证码、恢复码、设备与待处理事项。批量控件与筛选区并列常驻，手机双列、Pad 四列排布，并按适用性禁用。只有认证设置作为人事信息的下级页签保留。
- 普通用户的“账号与登录”继续作为人事资料卡的次级分区；设备卡片必须复用人事卡片的三套设备密度。
- 登录设备信息只作可选展示，不参与认证、续期或会话互斥；信息缺失时显示通用会话，不得阻断登录，也不得使用 OpenID、学号、姓名、IP 或硬件指纹猜测设备。同一账号允许多设备同时保持登录。
- 全局补充资料按“自然人 + 去除首尾空格的字段名称 + 完全一致的字段类型”唯一；待审核值不覆盖已生效值，不同名称或类型不合并。
