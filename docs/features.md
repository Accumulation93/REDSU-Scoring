# WHUSU Smart Workspace 功能口径

本文件记录人事领域整改后的用户功能与跨模块行为。视觉细节以 `docs/ui-kit.md` 为准，领域关系以 `docs/architecture.md` 为准。

## 人事目录与岗位

- 管理端“成员资料”一次展示当前权限范围内的全部在职与已离开成员，一人一卡；不得设置独立“已离开成员”页签。详情中展示该成员在当前组织的 0..n 个当前或离任前岗位。
- 在职无岗位成员仍在目录中，显示中性“暂无岗位”状态，可以维护资料和账号联系信息，但不拥有岗位规则权限。
- 已离开成员使用灰蓝状态气泡，详情为只读并展示离任时间、离任前岗位、组织资料、账号状态和历史；“重新加入”只恢复在职无岗位状态。
- 新建或编辑岗位依次选择岗位性质、部门、身份类别、可选职能组。系统自动生成岗位标签，不提供岗位名称输入框。
- 同一成员不得保存两条岗位性质、部门、身份类别、职能组完全相同的在职岗位；发现重复时保留原岗位并提示管理员修改，而不是静默创建重复工作角色。
- 职能组随部门联动；选择不属于当前部门的职能组必须在前后端都被拒绝。
- 删除岗位只影响该岗位，不自动离任；“离开当前组织”停用成员关系及其全部岗位、清空当前岗位兼容快照，同时撤销该组织的普通管理员授权、权限覆盖和管理员上下文会话；离任前岗位仍按离任批次只读展示。重新加入后保持在职无岗位，旧岗位和旧兼容快照都不得恢复。全局超级管理员治理权不由组织离任流程修改。

## 成员查询、筛选与导出

- 查询栏由“查询字段 + 关键词”组成，支持全部核心字段、姓名、学号、岗位性质、部门、身份类别、职能组、成员状态、账号状态和资料审核状态；补充资料字段不参与查询或筛选。
- 高级筛选支持成员状态、有无岗位、岗位性质、部门、身份类别、职能组、资料审核状态、资料完整度、合并账号状态和绑定状态多选；同类条件为 OR，不同类别为 AND。
- 岗位性质、部门、身份类别、职能组的组合必须由同一条岗位元组同时满足，禁止用岗位 A 的部门和岗位 B 的身份类别拼成虚假命中。筛选值使用组织字典 ID；同名部门、身份类别或职能组不得因名称兼容值相互命中。已离开成员使用离任前岗位参与匹配，并明确标注历史岗位。
- 支持姓名、学号、成员状态、岗位数量、资料状态、加入时间和离开时间排序；默认姓名升序。已选筛选以紧凑气泡展示，可单项清除或全部重置。
- 搜索和筛选在完整目录上本地即时执行；批量选择与导出只作用于当前可见且有权限的结果。导出补充成员状态、加入/离开时间和岗位性质列。

## 误导入永久删除

- 无业务记录的误导入成员可以永久清理。组织管理员可永久删除当前组织成员记录；超级管理员可在全组织预检通过后彻底删除自然人及其全局账号。
- 永久删除前必须展示全引用预检：业务事实记录作为阻断项，基础导入数据和未执行配置作为自动清理项，并显示清理后会被停用的零候选模板/规则。
- 组织范围删除不得影响其他组织或全局账号；彻底删除要求输入学号二次确认，禁止删除当前操作者和最后一名有效超级管理员。
- 删除执行使用版本校验、事务和幂等控制；一次确认只生成一个客户端幂等请求号，失败重试沿用该请求号，关闭确认层、切换对象或重新预检后重新生成。预检过期必须重新确认。完成后仅保留不含姓名、学号等明文的去标识审计。

## 工作角色切换

- 用户通过“工作角色”在组织岗位与管理权限之间切换；前端内部唯一当前键是 `activeContextId`，不得直接呈现给用户。
- 岗位角色展示生成的岗位标签和岗位性质；无岗位成员明确显示暂无岗位，不伪造岗位或默认部门；管理角色展示具体管理权限。
- 切换工作角色后，审核、场地和评分权限立即按当前岗位变化；旧请求、缓存和迟到响应不得覆盖新角色。
- 切换成功后统一回到应用门户并清空旧页面栈；再次进入任何子应用都按新角色完整初始化，效果必须与从门户首次进入一致，不复用切换前的页面、页签或加载状态。
- 门户顶部角色卡与应用权限使用同一份当前角色状态：管理权限显示深蓝管理主题，岗位显示标准蓝主题，颜色与可用入口不得出现不同步。
- 消息中心可以汇总当前账号可访问组织中的通知和待办，但每类待办必须先按目标组织内的实际权限过滤；没有资料审核权限的管理员不得看到待审人员姓名、学号或进入审核入口。消息跳转必须按通知所属工作角色选择用户端或管理端详情页，不能用同一固定页面代替两类角色。
- 登录过期后的自动恢复保持当前组织和工作角色；如果该角色已失效，当前操作会被取消并返回重新初始化后的门户，不会在系统选出的其他角色下继续执行。登录、续期与切换均不读取或校验设备指纹，多设备和 OpenHarmony 设备使用同一放行规则。
- 登录时偏好角色无法匹配而采用其他有效角色，不代表岗位资料发生变更，不显示“岗位信息已更新”提示，也不缓存或展示旧提示。当前组织与角色由共享 Hero 展示；实际角色失效、权限不足及旧操作取消的保护仍然保留。
- 门户、业务工作台和消息中心的 Hero 都按当前角色即时切换主题；管理权限统一使用深蓝主题，岗位统一使用标准蓝主题，不能只有门户颜色正确而子页面仍显示旧角色主题。
- 通知在目标页面成功打开且服务端确认后才标记为已读；跨组织或跨岗位消息先切换角色并重建页面栈，再通过短时一次性回执完成目标跳转。切换、跳转或已读写入失败时仍保持未读，待办也不会因为点击或清空通知而消失。

## 资料维护与审核

- 本人补充资料的读取和保存按服务端已认证账号的自然人及当前组织定位；微信登录、永久绑定和临时口令登录具有相同的本人资料能力，不得再次按旧微信绑定表找人，也不得为测试账号特殊放行。无岗位在职成员仍可维护本人资料；缺少成员资料时明确提示联系管理员，不能误报登录失效。管理资料接口复用已验证的管理角色与细权限。
- 个人资料页同时显示审核状态和完整度。待审状态不会因必填项尚未生效而消失。
- 人员维护者编辑已生效资料；资料审核员查看生效值/待审值对照卡，只能通过或填写原因驳回。
- 驳回原因必填并进入审核历史。导入、人工维护和审核通过使用同一全局生效值同步规则。
- 资料审核按成员记录 ID 精确处理；姓名或学号发生纠错后，原待审记录仍可正常查看和处理，不会因学号变化指向其他成员。
- 姓名/学号纠错先预览受影响组织、成员关系和账号；学号冲突必须进入显式自然人合并，不得直接覆盖或新建重复自然人。
- 补充资料日期只按日历日期处理并统一保存为 `YYYY-MM-DD`，不接受带时区的时间戳；文本长度按 Unicode 码点在导入、手工维护和审核入口统一校验。

## 账号治理

- 账号属于自然人并跨组织生效。成员卡只显示一个合并账号状态，详细设备和恢复信息位于成员详情。
- 只有 `auth.accounts.global_manage` 可以冻结、解绑或重置全局账号。具备该权限的管理员可以读取当前组织成员及账号状态，但不能因此编辑岗位或资料，也不能读取未获授权的其他组织；普通组织管理员看不到高危按钮，只能联系全局账号治理者。
- `auth.accounts.global_manage` 还可以为当前组织的在职成员初始化或修改登录口令；成员尚无账号或微信绑定不构成阻断，服务端按自然人复用或创建唯一全局账号。全局关闭口令登录时禁止设置口令。
- 未绑定成员首次使用口令验证成功后，系统只为该账号补充当前微信绑定，再建立统一会话；已有绑定不替换，当前微信已属于其他账号时拒绝绑定。修改口令保留既有会话。
- 已建账号但未绑定微信显示为“待激活”，没有账号才显示“未创建账号”，筛选与详情使用同一状态口径。
- 离开一个组织不冻结账号，也不影响该自然人在其他组织的成员关系和岗位。

## 审核审批

- 发起条件、候选人、指定审批人、待办和审批动作均按有效岗位计算，并在动作执行时按当前岗位复核。
- 跨组织待办可见，但用户必须切换到目标组织和满足规则的岗位才能处理。
- 发起与每一步处理保存不可变岗位/工作上下文快照；指定人员同时固化其岗位；历史始终显示当时岗位，缺失岗位快照时授权失败关闭。
- 无岗位成员不能发起或处理岗位规则驱动审核。
- 消息中心可汇总本人可访问组织中的实时待办和通知；待办随业务状态出现/消失，通知可单条已读、删除、全部已读或全部清除。全部清除只处理通知，跨组织部分失败时界面会回读真实结果。
- 从消息进入审核记录时，系统先切换到通知所属组织和岗位，再由详情页校验提交人、当前审批人、历史处理岗位或管理员细权限；可信页面地址本身不授予查看权。
- 审核附件的读取、预览、下载和验签使用同一组织与资源授权口径，并在下发前校验磁盘文件大小和哈希；文件缺失、被替换或存储位置异常时停止访问并提示稍后处理。

## 场地借用

- 一个场地可维护多条独立用户审批流程；新增流程先进入未落库草稿，保存时无 `flowId` 创建、有 `flowId` 精确更新，禁止回退覆盖第一条流程。
- 允许指定审批人时可选择多个岗位候选，任一候选岗位完成审批即推进该步骤；空选择表示不指定。直接通过与审批流程继续互斥，切换前必须明确确认。

- 申请人规则、审批候选、待办和审批动作与审核模块采用同一当前岗位模型。
- 审批流分别配置“允许指定第一步审批人”和“允许指定下一步审批人”。前者只控制发起借用，后者只控制审批推进；固定单流程开启前者时，发起页直接显示第一步指定入口。任一开关关闭时，前端隐藏对应入口，服务端同时拒绝越权参数。
- 审批历史从借用记录和审批快照实时匹配；一条借用只显示一条历史卡，详情显示本人处理步骤及后续进展。
- 无岗位成员可查看允许公开的场地和日程，但不能提交或处理岗位规则驱动借用。
- 同一岗位可以承担连续步骤；只有相邻步骤的标准化岗位规则完全相同且没有新指定审批岗位时，系统才在一次人工通过后自动通过后续等价步骤。规则范围变化、管理员步骤、不同职责或指定审批人都必须重新人工确认。
- 并行审批流是可选路线，一次操作只推进一条确定路线；某条路线完成后，其余路线记为被替代而非已完成。所有新借用在同一事务中冻结规则和流程，并在提交前确认首步存在候选人，避免产生无人可处理的待办。

## 考核评分

- 后台评分对象与记录按岗位建立，评分资格和动作只认当前岗位。
- 前端默认按自然人展示；仅当同一任务中同一自然人存在多个岗位记录时，追加部门、身份类别和职能组标签区分。
- 自评限制按自然人判断，切换岗位不能绕过；历史结果使用记录发生时岗位快照，禁止用当前资料回填缺失快照。
- 从评分表返回时保留被评分人列表并在后台更新状态，不重新用整页加载遮住目录。历史公示活动按管理员实际选择的活动加载，已指定评优名单不会因当前活动、岗位或规则界面切换而消失。
- 评优名单保存后作为公示活动事实保留；已有名单引用的规则条款不能直接删除，管理员需先调整名单后再修改规则，服务端禁止级联清空历史指定。
- 浏览结果公示及切换历史活动不会创建或修改公示配置，只有管理员明确保存时才写入。

## 字典治理

- 部门、身份类别、职能组是岗位与业务规则共享字典；职能组必须属于岗位部门。
- 任一字典项被岗位、规则、快照或历史引用后，删除操作必须被阻止，并向管理员展示引用类别与数量。

## UI 与可操作性

- 人事标题、筛选、批量操作、岗位组和资料对照区至少有一层蓝色轻奢玻璃语义容器。
- 资料对照卡保持“字段名 → 当前生效值 → 待审核值”的阅读顺序；手机纵排，Pad 可双列。
- 长弹窗使用固定标题、可滚动正文和固定底部操作栏；高度由内容和视口共同决定，手机、Pad 竖屏、Pad 横屏均能滚动到底并操作保存/取消。
- 所有提示、标签、空状态、确认文案和错误反馈进入 locale，不在业务代码中保留用户可见常量。

## 时间显示

- 数据库绝对时间统一按 UTC 保存，界面只按系统配置时区显示，不跟随手机、Pad 或开发者工具所在设备的本地时区。
- 列表时间显示为 `YYYY-MM-DD HH:mm`，详情、验签和安全记录显示为 `YYYY-MM-DD HH:mm:ss`；任何页面不得直接显示 ISO `T...Z` 原文。
- 纯日期、每日开放时间、时长、提前量和周期规则保持业务原值，不做时区偏移，避免日期跨日漂移。
- 历史来源不明的时间正常格式化显示；服务端按记录标识与原始绝对时间下发字段级 `*ReviewStatus`，界面只标记对应字段“历史时区待核对”，迁移不得猜测修改或用全局提示代替。

## 签署隐私与密码验签

审批通过、签名、盖章和驳回都为当前附件产生平台托管密码凭证，最终 PDF 绑定当轮完整清单。姓名可公开，学号只参与服务端受保护核验，同名人员以唯一身份及事件关联区分。

上传验签直接检查上传字节，不以查到申请记录为前置条件；正常签名、篡改与未签名文件各自返回真实检查结果。当前组织无匹配申请时仅检查文件，不泄露人员资料，并把“文件签名有效”与“平台经办人身份未确认”分开显示。

普通/管理端共用四态结果，默认按用户视角展示文件、逐步经办人、签署时组织/岗位与身份核实结果，区分本人上传文件、平台保存文件和仅查询。专业检查进入独立验证报告，提供公开证书导出与第三方阅读器使用说明，不展示系统原因码。历史原文件保留，在途不足不补造事实。缺少外部 CA/TSA 核验条件明确未确认，不把平台证明说成个人独占私钥或第三方可信时间。见 [协议与部署说明](pdf-signing-trust.md)。
