# 页面模板清单

## 人员选择弹窗接入模板

业务页面注册 `/components/personnel-picker/personnel-picker`，传入完整候选 `options`、当前已选 `value`、`selectionLevel` 与 `multiple`。页面负责接口加载和确认后的业务保存，组件负责搜索、同岗位元组筛选、草稿选择、取消回滚、清空确认及手机/Pad 竖横屏滚动。不得在页面重新创建候选卡片或筛选状态机；额外业务字段通过 `slot="extra"` 注入。

```json
{ "usingComponents": { "personnel-picker": "/components/personnel-picker/personnel-picker" } }
```

```xml
<personnel-picker visible="{{pickerVisible}}" title="{{pickerTitle}}" options="{{candidates}}" value="{{selectedItems}}" selectionLevel="assignment" multiple="{{true}}" loading="{{loading}}" errorText="{{errorText}}" bindconfirm="confirmPersonnel" bindcancel="closePersonnel" bindretry="loadPersonnel" />
```

自然人授权将 `selectionLevel` 改为 `person`；审批或指定保持 `assignment`。确认处理器从 `e.detail.keys/items` 一次写回，取消处理器只关闭弹窗。

## 共享工作台模板

专项契约索引：分包边界与 locale 见 [module-boundaries-and-language-migration.md](module-boundaries-and-language-migration.md)，签名坐标、场地规则编辑器和审批历史详情见 [ui-kit.md](ui-kit.md)，弹窗滚动见 `.agents/skills/wechat-popup-scroll-contract/SKILL.md`。本页只描述页面结构，不复制这些硬契约。

适用于门户、消息中心和所有登录后的子应用页面。

1. 原生导航栏：页面名称 + `WHUSU智慧工作台`。
2. `workspace-hero`：姓名、当前岗位或管理权限、当前组织、工作角色切换入口。
3. 主内容卡片：根据页面类型选择列表、统计、表单或详情模板。
4. 非阻塞状态：加载、空数据、错误、权限变化和部分失败。
5. 页面底部操作：只保留当前页面必要的返回或提交操作。

## 列表模板

- 顶部标题和必要筛选。
- 筛选项使用紧凑表单控件，不用胖胶囊按钮。
- 列表行显示主标题、组织/身份元数据、描述和时间。
- 必须提供加载、空数据、错误、权限不足状态。
- 手机单列；Pad 竖屏可使用两列摘要；Pad 横屏按内容决定整行或多列。

## 详情模板

- Hero 下方先展示最重要的状态和摘要。
- 详情字段按语义分组，不把岗位细节挤入人员摘要卡片。
- 长内容进入明确的弹窗正文或页面滚动区。
- 修改、重新提交、撤回、审批等操作放在固定的操作区，避免和背景页面混在一起。

## 创建/编辑模板

- 标题、说明、表单分组、校验反馈、保存/取消操作。
- 表单控件使用 `.field-input`、`.field-textarea`、`.picker-value` 等原语。
- 保存中、保存成功、保存失败和权限变化必须有页面内反馈。
- 弹窗编辑只让正文滚动，标题、底部按钮和遮罩保持稳定。
- 弹窗的遮罩与外部页面滚动位置无关；手势落在内层列表时先滚动内层，落在正文其他区域时才滚动正文，背景页面始终锁定。
- 单一表单或详情由统一正文表面直接承载；只有同时存在摘要、筛选、独立列表或不同业务区域时才使用分区卡。短确认框只保留一张内容卡和独立操作区，不制造无意义套娃。
- 多分区窗口使用透明堆叠正文，分区本身承担视觉边界；禁止“正文卡—唯一分区卡”或“身份总览卡—组织卡—岗位卡”这类没有新增语义的重复包裹。
- 手机、Pad 竖屏、Pad 横屏分别使用舒适、稳定、紧凑但不贴边的弹窗密度，任何方向都必须保持标题、正文卡片和底部按钮左右对齐。
- 创建和编辑窗口应使用适中的可视宽度承载字段，不得按内容收缩成窄列；外壳、正文表面和功能分区分别保留四向间距，标题与关闭操作也不能贴边。
- 表单字段、标签、同排控件和操作区分别使用 `--ui-field-gap`、`--ui-label-gap`、`--ui-inline-gap`、`--ui-action-gap`；末字段不再通过 margin 为底部按钮占位。提交/保存/取消位于正文外的 `.ui-dialog-footer`，正文禁止使用大块底部 padding 模拟操作栏。

## 门户与应用服务模板

- 门户始终显示全组织汇总；应用服务使用三列手机、四列 Pad 竖屏、五列 Pad 横屏的 Grid。
- 最后一行不做两端拉伸；应用数量不足时保持正常尺寸并居左。
- 横屏使用固定五列轨道，最后一行不改变卡片宽度，也不为了“撑满”重新分配剩余空间。
- 当前工作角色摘要和组织切换入口位于共享 Hero 内，不另起一套顶部卡片；具体类型显示为岗位或管理权限。
- 门户待办/通知预览最多 3 条高度、框内滚动；完整列表由“查看全部”进入消息中心。
- 预览行使用受控语义图标尺寸；类别与身份位于上下文行，完整组织名称与当前标识独占下一行。Pad 横屏不得沿用手机 rpx 放大图标。
- 底部组织/身份与退出登录使用专用操作间距，Pad 默认两列；品牌名称区通过专用页脚间距与按钮组分开。

## 消息中心模板

- 顶部是组织范围选择行和两个消息页签。
- 每条通知/待办显示组织完整名称、当前组织标识和业务类别。
- 消息行与门户预览使用同一媒体行契约：图标顶部对齐、正文可收缩、类别不拆字、组织整行显示，尾部操作占固定通道。
- 跨组织打开事项只使用项目自绘确认层；确认切换成功后再标记已读和跳转。
- 部分组织失败使用非阻塞提示条，不反复弹系统 Toast。

## 管理端模板

- 管理页面使用紧凑工作台 Hero 和统一页签。
- 列表、筛选、编辑和批量操作保持同一层级，不使用页面级大块空白。
- 分区标题、二级页签和批量操作共同放入 `.section-control-card`，不得直接暴露在透明工作台或 `.section-stack` 上；纯布局容器不算视觉包裹。
- 筛选区同排的日期/时间选择器和清除按钮使用 `.ui-inline-control-row` / `.ui-inline-control` 共享物理高度与垂直基线；带标签的并列筛选字段使用 `.ui-inline-field-row` 对齐实际控件底边。标题旁的宫格/列表切换使用紧凑分段控件，不得挤压标题或套用整行主页签高度。
- 列表卡片的小型查看/编辑/删除/移除统一使用 `.card-actions` 独立分隔行并右对齐；危险操作使用红色语义。可展开卡按“摘要与展开入口 → 操作行 → 展开内容”排列，禁止操作按钮绝对定位覆盖展开控件。
- 权限、身份、组织和人事页面都必须显示当前组织范围，超级管理员的全局身份不按组织复制。
- 人员认证和账号恢复属于成员资料本身。成员外卡和详情摘要只显示同一个合并账号状态；“查看/编辑 → 账号与认证”不再用字段卡重复显示当前状态、微信绑定或笼统的恢复方式，只保留认证码、恢复码、设备、待处理事项及对应操作。批量操作与筛选控件并列常驻，手机双列、Pad 四列，不另套独立模块；不适用时使用统一禁用态。认证设置仅作为“人事信息”的下级页签。不得设置重复认证目录，也不向管理员展示内部操作日志。
- 成员外卡批量选择使用独立等宽紧凑胶囊（选择/取消，不带 ✓），固定在卡片左上并作为第一个可见子项；不得嵌入姓名、学号、身份或状态气泡。查看/编辑、删除等行内操作使用标准按钮大圆角档，账号状态气泡使用紧凑圆角档。
- 账号目录和待认证人员先一次加载当前权限范围内的完整数据，再在本地即时搜索和筛选；长目录可以分段渲染，但不能通过接口静默截断。
- 单人冻结、解冻、退出设备等行级操作只更新对应记录，必须保留当前页签、筛选条件、选中项和滚动位置。
- 字典目录加载失败时保留最近成功数据并在原表面显示失败说明和重试；成功空数据才显示空状态。删除被引用字典项时，用受控弹窗展示引用类别与数量，不把服务端明细压缩成 Toast。
- 自然人级管理员候选一人一卡，但检索和卡内岗位信息必须遍历全部岗位元组；后续岗位可以命中，顶层旧岗位快照不得参与。

### 人事成员目录模板

- 人事二级模式仅为“成员资料 / 认证设置”。成员资料默认包含在职和已离开成员，状态通过气泡和筛选区分，禁止新增独立离任目录。
- 查询字段、关键词、排序、高级筛选和批量工具共同置于 `.section-control-card`；高级筛选在卡内展开，已选条件以紧凑气泡显示并支持单项清除/全部重置。手机单列或双列组合，Pad 使用紧凑网格。
- 外卡一人一卡，只展示核心摘要；岗位在详情中分组。已离开成员使用灰蓝状态，显示离任时间；详情只读、岗位标记为历史，仅提供重新加入。
- 人员筛选的岗位维度必须由同一岗位元组共同满足。批量选择与导出只作用于当前可见且有权限的结果，并保持当前筛选、排序与滚动状态。
- 永久删除入口只在详情危险操作区出现。预检弹窗采用固定标题、滚动正文和固定操作栏，按阻断项、自动清理项、待停用规则分组；彻底删除自然人要求学号二次确认。
- 所有人员、岗位、身份类别、部门、职能组、规则和对象卡片选择器遵循统一结构：一张卡一个选项，左上独立“选择/取消”，信息气泡只读；人员多岗位拆卡。候选区与已选区都不得使用身份气泡或整行“移除”操作表达选择状态。
- 人员岗位卡用 `assignmentId` 选择并按同一岗位元组筛选；自然人级账号/认证授权属于显式例外。导航型即时单选卡可省略选择胶囊；规则卡的编辑/删除操作必须与选择摘要分行。

### 时间展示模板

- 列表页只绑定按系统时区预计算的分钟精度文本；详情、验签与安全记录绑定秒精度文本。不得直接绑定原始绝对时间或显示 ISO `T...Z`。
- 纯日期、每日时刻、时长、提前量和周期规则使用各自业务格式，不套用绝对时间转换。历史时区待核对必须由当前记录对应的字段级 `*ReviewStatus` 触发灰蓝辅助提示，不得使用全局提示污染已确认时间。

## 普通用户人事信息模板

- 人事信息仍以个人资料和岗位信息为主体，“账号与登录”作为同一资料卡中的次级分区，不另设账号安全子应用。
- 恢复码、登录口令和登录设备按策略显示；没有可用恢复方式时只说明联系管理员，不展示内部认证状态或安全日志。具备 `auth.accounts.global_manage` 的管理员可为在职但无账号或未绑定微信的成员初始化口令。普通用户的“保存口令”使用全宽标准主按钮，管理详情使用与“保存人事信息 / 关闭”同规格的“保存口令 / 取消”双按钮行，禁止使用紧凑按钮。
- 生成凭据只显示一次，设备退出只移除对应设备行，不刷新整张人事信息卡。
- 登录设备信息只作可选展示，不作为登录或续期条件；信息缺失时使用通用会话文案，同一账号允许多设备同时在线，不以 OpenID、姓名、学号、IP 或硬件指纹猜测或合并设备。
- 同一自然人的跨组织补充资料按“字段名（去首尾空格）+字段类型”复用；只有已生效资料参与合并，待审核资料继续保留在所属组织，冲突按最新生效时间处理。

## 设备模板差异

| 模板 | 手机 | Pad 竖屏 | Pad 横屏 |
| --- | --- | --- | --- |
| 页面边距 | rpx，适合单手触控 | 逻辑 px，内容列居中 | 逻辑 px，工作区铺满 |
| 页签 | 手机高度和内边距 | 更矮、更密 | 整行均分，横向工作台 |
| 卡片 | 较柔和圆角和较宽内边距 | 半径与内边距收紧 | 半径更克制、上下间距最小 |
| 按钮与气泡 | 主按钮 28rpx、紧凑控件 18rpx | 主按钮 14px、紧凑控件 12px | 主按钮与页签 12px、紧凑控件 11px |
| 字体 | 紧凑但可读 | 明显大于手机 | 大于手机但不随宽度无限放大 |
| 弹窗 | 居中或底部 sheet | 居中、宽度受限 | 居中、相对完整视口 |
